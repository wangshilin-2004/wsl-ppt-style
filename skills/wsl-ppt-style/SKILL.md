# 世林的 PPT 风格

目标：组会模板下的高密度技术讲解。页面紧凑规整，图文互相解释，机制与证据充分展开，最后用一句话收住重点。

## 先确定本次用途

- 课堂/组会/答辩：阅读 [布局与视觉](references/layouts.md)，按需阅读 [讲解与场景](references/teaching.md)。
- PPT 教材或科研配图：阅读上述两份参考的配图部分；不把汇报模板的校徽、页眉、页底总结套进独立插图。
- 明确更新本技能：阅读 [更新方法](references/update-style.md) 和 [偏好依据](references/evidence.md)，做针对性修改。

将本技能作为风格依据，与当前可用的演示文稿技能/工具配合。不要把风格要求当作强制使用某种编辑器、导出格式或发布渠道的理由。

## 优先级

本次明确要求优先；其次是近期明确反馈，再其次是适用场景的稳定偏好，最后是旧作品中的观察。旧稿中的偶然排版、页数和瑕疵不自动成为规范。

已有模板或参考稿时先检查并继承其结构。若存在 `.local/reference-paths.json`，可读取其中的本机参考路径；按用途读取最相关的文件，不必读取所有作品。不存在或不可访问时使用文字规则，并说明不能精确复用原模板，继续完成可执行工作。

## 制作时的核心要求

1. **紧凑而有层次。** 内容页信息密度高，减少大框内的无效留白；同时保留清楚的内边距，不让文字贴边或与图标拥挤。先调整分区比例、删重复句，再考虑字号。
2. **分区与关系一起设计。** 同级模块保持协调的尺寸、间距和对齐。网络、流程允许错落布局，但连线必须清楚。每个框要承担实际内容组织作用。
3. **图文对应。** 架构图配机制解释，时序图配执行步骤，实验图配条件和结论。优先使用清晰图标；避免用随意拼凑的小形状假装设备图标。
4. **关键证据完整。** 少页数的同时保留必要背景、核心思想、方法实现与关键实验。数字标明对象、基线、单位和条件；不把不同场景的最大收益合并。
5. **结论落在页面。** 适合时采用顶部主题、中部图文、底部一句提炼的结构。课堂/组会近期默认偏好是居中的红色总结语；若用户要求严格跟随深蓝底白字的旧模板，保留该模板。
6. **语言生动准确。** 简短、直接、有具体动作。概念首次出现就解释，用图或小例子帮助半小白理解；保留必要实现边界和回退条件。
7. **讲清价值与不足。** 论文分享包含具体局限、证据缺口或值得验证的问题，区分作者结论与自己的推测。可以讨论 AI Infra / 投机解码方向，但共享材料不引入用户未要求公开的个人研究内容。

## 交付前检查

实际查看渲染页面，重点检查：大块无效留白、字贴边、字号过小、框和图标不协调、同级模块间距不齐、箭头误导、文字截断、图表标签看不清、红色总结未居中。修正问题时同时检查相邻元素。

检查图、文字、讲稿是否互相对应；首次出现的概念是否解释；实验的比较基线是否交代；结论是否超出证据。根据本次时长安排内容，不把以往“十分钟”或某个页数当成永久限制。

一般制稿只读取本技能。仅当用户要求学习、记住或更新风格时修改对应规则；更新本地规则与同步 GitHub 分开处理，不默认执行后台同步或发布。
