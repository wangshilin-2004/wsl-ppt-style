# 布局与视觉

## 汇报稿的稳定外观

- 常用 16:9、白底和蓝色主调。已有组会模板时保留顶部横条、章节编号、学校标识及固定位置，不另造品牌风格。
- 蓝色组织整体结构，红/绿/橙用于重点或机制区分。相同组件跨页尽量保持颜色一致，不机械规定每种语义必须使用某个颜色。
- 原稿可见深蓝 `#0C306E`、强调蓝 `#1A56B8`、浅底 `#F5F8FC`、深红 `#C00000`、绿 `#198C4B`、橙 `#E8611A`。这些是缺少模板时的参考值，不要求覆盖原模板色。
- 汇报稿中文主要用微软雅黑 / Microsoft YaHei，英文和数字随模板，常见 Arial 或 Times New Roman。避免全局强制宋体。
- 标题明显高于正文层级，模块标题突出，图注退后。字号按原模板、投影可读性和内容调节；旧稿中的小字号不作为压缩内容的借口。
- 封面、目录、结束页可以留白。高密度主要用于内容页。短课堂分享减少重复目录，答辩可保留章节导航。

## 可复用的页面结构

按内容选择，不要求每页同一种排版，也不要求凑满固定模块数。

| 内容 | 合适的构图 | 必须讲清的对应关系 |
|---|---|---|
| 场景与问题 | 一侧场景/流程，另一侧问题；页底提炼动机 | 现象为什么构成系统问题 |
| 多个问题与机制 | 按行对应问题、目标、措施 | 每种机制到底解决哪一个问题 |
| 系统总览 | 大架构图 + 邻近的机制解释 | 数据流、执行主体、组件协作 |
| 单个机制 | 流程/时序图 + 步骤、条件、回退；必要时小表或公式 | 什么时候触发、实际做什么、何时失效 |
| 实验 | 可读的大图 + 精简数据/解释，重要指标就近强调 | 实验条件、基线、收益与代价 |
| 总结与思考 | 贡献和证据对应，局限与验证建议成组 | 已证明什么、尚未证明什么 |

底部提炼句应该概括本页已经建立的结论，避免空泛口号或重复标题。课堂/组会按近期要求优先红字居中；完整套用旧模板时可沿用深蓝底白字。正文段落通常左对齐，短标签、同级比较块按视觉关系居中，不强制所有文字居中。

## 密度与细节

- 框内出现大空白时，优先缩框、扩大主图、重排图文比例，或合并紧密相关的内容。
- 太挤时，先删重复说明、整理层次、放宽真正复杂的区域；必要时合理拆页。
- 保持同类模块等宽或视觉重量相近；关系图可以非对称，但应有稳定阅读顺序。
- 连线避开文字和图标；箭头端点、跨层对应、输入输出的归属要明确。
- 图标轮廓完整、风格协调。阴影如使用应轻、连续、自然，不遮挡关系。
- 立体分层仅在能清楚表达层级时使用。二维更易理解时使用二维；不要因参考图立体就强行立体化所有元素。

## 独立科研/教材配图

图的范围按关系组织，不套用整套汇报外框。用流程、并排比较、结构示意、图例和紧凑对照表解释机制；图文术语和正文一致，不添加正文没有的事实。

中文宋体、英文和数字 Times New Roman 是已有教材配图任务中的明确要求，适用于该类任务或用户再次指定时。保留足够可读字号，同时避免文字挤出框。编辑性按用户任务保留，不把复杂机制草率压成不可修改的整图。
